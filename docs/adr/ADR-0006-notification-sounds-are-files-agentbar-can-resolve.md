# Notification sounds are files AgentBar can resolve

## Context

Step 07 ships a **provider × event → sound** matrix. Its own specification opens
with the hazard that makes the feature hard:

> `UNNotificationSound(named:)` **silently falls back to the default when the
> file is missing.** Validate existence explicitly at selection and at send time,
> and show the user when a chosen sound is unusable — otherwise the setting
> appears broken for no visible reason.

The API takes a **file name**, never a path, and resolves it in exactly two
locations: the app's own bundle, and `Library/Sounds` under the app's container —
for an unsandboxed app, `~/Library/Sounds`. `/System/Library/Sounds` is not one
of them, verified on macOS 27.0
([platform-integration.md §6.1](../dev/platform-integration.md)).

The initialiser cannot fail. It returns a sound object for any name at all, and
the substitution happens later, inside the notification system, with no error, no
log line and no API to interrogate. A user who picks `Glass` and hears the
default sound has no way to find out why, and neither has AgentBar.

So the question is not "how do we validate a sound file". It is **what may
appear in the picker at all**, because anything offered that cannot be resolved
is a setting that will silently do nothing.

## Decision drivers

- The project's rule that no failure is silent. A sound that quietly does not
  play is exactly the kind of failure `CLAUDE.md` forbids.
- The sound matrix is the step's headline feature; a picker that lies about what
  it can play makes the whole feature untrustworthy.
- macOS's own system sounds are what a user will reach for first. `Glass` and
  `Basso` are the vocabulary they already have.
- AgentBar has no licence to redistribute Apple's audio files.
- Whatever is chosen has to stay checkable **later**: `~/Library/Sounds` is the
  user's own folder and they may empty it at any time.

## Considered options

**1. Offer the system sounds and hope.** List `/System/Library/Sounds` in the
picker and pass the names through. Rejected: every one of those choices would
resolve to nothing, and the failure is exactly the invisible one the step exists
to prevent. It also cannot be validated — the file is genuinely there, so a
filesystem check would pass while playback still substituted the default.

**2. Ship copies of the system sounds inside AgentBar.app.** Resolvable and
familiar. Rejected: they are Apple's files and redistributing them is not
AgentBar's to do.

**3. Play the sound ourselves with `NSSound` and send a silent notification.**
Every file on disk becomes usable, from any location. Rejected, and this is the
serious one: the notification system honours Focus, Do Not Disturb, the per-app
sound switch and the user's output-device routing. A sound played beside the
notification honours none of them, so an agent finishing during Do Not Disturb
would make a noise the user explicitly asked not to hear. Correct behaviour in
the quiet cases matters more than a wider catalogue.

**4. Offer only what the notification centre can resolve, and offer to make more
of it resolvable.** The picker lists AgentBar's own bundled sounds and whatever
is in `~/Library/Sounds`. **Add Sound File…** validates any file the user picks
and copies it into `~/Library/Sounds`, opening at `/System/Library/Sounds` so
the sounds they were going to ask for are the first thing they see.

## Decision

**Option 4.** Every selection in the matrix names a file AgentBar can `stat`,
which is what makes reporting a broken sound possible at all.

Concretely:

- AgentBar ships four authored sounds — Question, Waiting, Finished, Failed — at
  the **top level** of `Contents/Resources`, generated by
  `scripts/make-sounds.py` and asserted present by `make verify-bundle`. They are
  the defaults, so a fresh install has a working matrix with no system sound in
  it anywhere.
- The picker lists those, plus every valid file in `~/Library/Sounds`, plus
  **Default** and **None**, which need no file.
- Importing copies rather than references, validates before copying, never
  overwrites an existing name — a collision takes `Chime 2.aiff` — and never
  touches the original.
- Validation is `AudioFileGetProperty`, not a guess from the extension:
  container, encoding and duration, checked when the picker is built **and**
  again at send time.
- A selection that has become unusable falls back to `.systemDefault`, not to
  silence, and the problem is recorded on the matrix row that caused it. A
  misconfigured sound must not also cost the user the notification's arrival;
  silence is a choice they can make on purpose and is never an error state.
- The settings window can play any selectable sound. Validation proves a file
  loads; only a person can confirm it is the sound they wanted.

## Consequences

**Good.** Nothing in the picker can silently do nothing. Every failure mode has
a sentence attached to it and a row to show it on. The user's own sounds are
first-class, and getting a system sound takes one extra click that leaves them
with a file they can also choose in System Settings.

**Bad.** `Glass` is not in the list until the user copies it in, which will
surprise someone. The footnote under the Sounds section says why in one
sentence, and the file picker opens at `/System/Library/Sounds` so the answer is
where the question is asked.

**Bad.** AgentBar writes into `~/Library/Sounds`, a directory it does not own. It
only ever adds, never replaces, and the folder is the documented home for a
user's own sounds — but it is still the user's folder, so **Reveal Sounds
Folder** sits next to the import button and the copy is announced.

**Neutral.** The four authored sounds are machine-generated additive synthesis.
`scripts/make-sounds.py` is committed so a voice can be changed by editing four
lines and re-running it, rather than by finding whoever made the file.

**Consequence for step 09.** Codex gets its own column in the matrix and needs no
new sound machinery: the catalogue is provider-neutral and the defaults are
per event, not per provider.
